# Experiment 002: Constant-LR Rerun

## Summary

| Item | Value |
|------|-------|
| Dates | 2026-06-10 to 2026-06-11 |
| Status | Completed |
| Purpose | Repeat the comparison without LR decay for few-billion-token training |
| LR schedule | 100M-token warmup, then constant `3e-4` |
| Output root | `runs_constant/` |

This run addressed the concern that a few-billion-token experiment should not
spend most of training in LR decay. The random baseline ran as one job. The
experimental path ran shuffle 1B and then normal 3B in one Slurm job.

## Generation Evaluation

Qualitative prompt samples showed both models remained weak and repetitive. In
manual spot checks, the shuffle path was sometimes more directly on topic, but
not consistently less repetitive.

DeepSeek force-choice blind judging used `deepseek-v4-flash` on 180 paired
samples generated by `sbatch/generate_constant_blind_eval.sbatch`.

## Interpretation

Constant-LR training produced a clear training-loss advantage for the
shuffle-initialized path. However, this completed-run generation evaluation did
not show a statistically significant DeepSeek preference and did not improve the
simple repetition metrics.

## Caveats

- This experiment still used the pre-fix local JSONL data pipeline without DDP
  rank sharding. Reported tokens overstate distinct text-token coverage by about
  2x.
- Token-id shuffle was active during shuffle pretraining; the issue was duplicate
  text streams across ranks, not disabled token-id permutation.
